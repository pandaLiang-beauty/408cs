# 真题关联强化题库

每道历年真题（选择题和综合题）提前建立关联题索引。组卷只查询已发布索引，不现场调用模型，不用知识点标签直接补满题数。

## 当前规则

2026-09-29 用户最终决定只保留 `step-5-preview` 和 `deepseek-v4-flash`，不再使用 Qwen 或 Gemini。两者均使用 `https://api.ncnb.me/v1`，独立接收题干、选项、参考解析和原图，彼此不共享评分。

1. 对完整题库生成内容指纹。保留原标签，结合题干与选项中的明确术语补充检索标签，按较宽知识范围召回候选；补充信息只保存于索引。
2. 对全部真题生成候选，包括经典练习、模拟题和其他年份真题，支持选择题与综合题互相关联。排除自身和内容相同的复制题。
3. SVG 在浏览器中渲染为图片，位图保留原内容。Step 与 DeepSeek 直接读原图，不经过文字转录。
4. 两个模型分别给每组有向关系打 0--100 分。达到 75 分必须说明具体共同技能，**两者均达到 75 分才接受**，按平均分排序。仅同章、共有名词、实际解法不同的题不应通过。
5. 所有候选完成双模型评分、题目指纹一致后才可发布。没有足够相近的题可保留空列表，不编造匹配。

## 组卷

- 从实际做错或模糊过的真题出发，读取关联列表，按到期时间轮流选题。普通强化卷只选选择题，最多 50 道；周日单独安排全是综合题的大题强化卷，最多 20 道，不用另一题型补足数量。
- 周日按北京时间 08:00 切换的学习日计算，独立安排一份大题强化任务，未完成的旧任务仍保留。周一至周六继续原来的真题与选择题强化交替顺序，周日不占用交替位置。尚未开始的当日/未来周日任务会调整为大题强化，已开始的卷不改写。
- 两种强化卷分别建卷和续做；旧的混合卷仍可通过原任务/记录继续。大题强化每页两题，允许先交卷结束当天任务；未批改的大题仍保留在本场记录中，之后可继续作答并单题 AI 批改。
- 关联程度优先。同一个 5 分区间内优先新题，其次曾错或模糊的题，再其次其他有记录的题；随后按精确分数及题源排序。
- 去重，保持 12 小时再次出现间隔，保留尚未整卷完成的 2024--2026 年模考卷。
- 新强化题记录来源真题。同一来源在本卷的所有关联练习完成批改后，按最弱结果结算一次来源复习时间，避免一卷连续升级。逐题到期时间优先，旧记录没有逐题调度时使用知识点到期时间。
- 已开始的卷及历史作答不重组。题目内容变化造成指纹不符时，旧关系停止参与推荐，需重新离线评估。
- 50 题是每卷上限，不是每天必须完成的数量，也不限制一天主动创建多卷。

## 运行

在 `backend/` 下执行。默认版本为 `relations-v6-step-deepseek`，工作库为 `data/relations/scoring-v6-production.db`，路由文件为 `data/relations/routes-v6.json`，其内容为 `{"default":"gateway.json"}`。凭据不入版本库，密钥文件权限为 600。

```bash
.venv/bin/pip install -r relations-requirements.txt
.venv/bin/python build_relations.py prepare
.venv/bin/python prepare_relation_figures.py --browser /path/to/chrome
.venv/bin/python build_relations.py watch --detach --workers 13 --timeout 300
.venv/bin/python build_relations.py status
.venv/bin/python build_relations.py inspect --source-ids 14,42
.venv/bin/python build_relations.py publish
.venv/bin/python build_relations.py publish --apply
```

`status` 默认显示适合终端阅读的总评分百分比、每个模型的完成百分比与剩余量、全部模型均已评完的题对比例，以及实时待完成批次数。百分比按保存的评分计算，不按大小不一的批次数计算；复用分数和部分成功结果均计入，失败重试不重复计数。剩余时间按近 20 分钟成功批次的实际吞吐粗估，样本不足、长时间没有新结果或任务暂停时不显示猜测值。状态查询只读，不需要重启或停止评分进程，也不涉及前端。

终端每 5 秒刷新一次，按 Ctrl+C 只退出查看，不停止评分：

```bash
watch -n 5 '.venv/bin/python build_relations.py status'
```

脚本读取结构化进度可用 `.venv/bin/python build_relations.py status --json`。终端中的待完成批次数每次重新统计，不使用 `worker_state` 中开跑时的旧计数。

Step 保持 5 并发，DeepSeek 评分保持 8 并发，总线程数为 13。每批最多 192 组有向关系，一批可含多个原题及各自候选，原图跟随对应题号发送。各模型队列独立补充任务，较快模型不必等待慢模型整轮完成。路由中的 `enabled`、`concurrency` 是动态运行参数，不改变评分版本。

`run` 和 `watch` 支持断点续跑，已完成任务不重复请求。保存原始响应、耗时和错误；合法的部分评分仍保存，下次只补评缺少或不合法的关系。支持 `--source-ids`、`--limit-jobs` 和 `--models`，但发布始终要求完整双模型结果。

使用流式接口减少网关超时。普通 429 重试失败后暂停该模型派发 60 秒，DeepSeek 同时减半并发，Step 退避后仍以 5 为目标。额度用尽或鉴权失败暂停相应模型，不降低审核条件。

工作库有进程锁，禁止两个写入任务同时运行，只读查询不受影响。SIGINT/SIGTERM 停止领取新任务，等待在途请求保存后退出。`watch` 同一任务最多尝试 12 次，最多运行 24 小时；`--detach` 保存持久日志和 PID。完整结束时仅校验并标记 `ready_to_publish`，**不会自动发布或重启线上服务**。

日志和 PID 分别为 `data/relations/scoring-v6-production.log`、`data/relations/scoring-v6-production.pid`。停止前须确认 PID 对应本仓库进程。
